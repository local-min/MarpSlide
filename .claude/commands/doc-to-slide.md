ドキュメントまたはトピック説明からスライドを生成する: $ARGUMENTS

## 処理フロー

### 1. 入力の判定と読み込み

- `$ARGUMENTS` がファイルパス（`.md`, `.txt`, `.pdf` 等）の場合、Read ツールでファイル内容を読み込む
- ファイルパスでない場合、テキスト自体をトピック説明として扱う
- 入力が短いトピック説明（1-2文）の場合、その内容を核にスライド内容を構成する

### 2. リファレンス読み込み

以下のファイルを読み込んで参照する:

1. `docs/style-guide.md` — カラーパレット、タイポグラフィ、ライティングルール
2. `docs/pattern-guide.md` — コンテンツ種類→パターン番号のマッピング、目的別スライド構成
3. `slides/template.md` — frontmatter とTailwind CDN ボイラープレート
4. `slides/example.md` — 63パターンの実装リファレンス（該当パターンのみ参照）

### 3. ドキュメント診断

入力コンテンツの情報充足度を診断し、不足があればユーザーに質問して補完する。

#### 3a. プレゼン目的の仮判定

入力コンテンツを読み、以下の表からプレゼン目的を仮判定する:

| 目的 | 判定基準 |
|------|---------|
| research | 研究課題、実験、結果、考察、参考文献がある |
| business | 顧客、価格、売上、ROI、提案、市場がある |
| technical | アーキテクチャ、API、コード、デプロイがある |
| educational | 学習目標、概念説明、例題、演習がある |

目的が明確に判定できない場合は「不明」として、3c の質問に含める。

#### 3b. 情報充足度チェック

以下の3カテゴリで入力ドキュメントを診断する。各項目を「充足」「部分的」「欠落」で評価する。

**メタデータ:**
- プレゼンタイトルが明確か
- 著者・日付が特定できるか
- プレゼン目的が明確に判定できるか

**コンテンツ完全性（目的別の必須要素）:**

| 目的 | 必須要素 |
|------|---------|
| research | 背景・動機、研究課題/仮説、手法、結果データ、考察、貢献 |
| business | 課題/ペイン、解決策/提案、市場データ、実績指標、CTA |
| technical | 概要/背景、アーキテクチャ、主要コンポーネント、性能データ |
| educational | 学習目標、前提知識、概念説明、具体例/演習 |

**データ充足度:**
- メトリクスやチャート用の数値データがあるか（最低3つの数値）
- 比較・対比の要素があるか（Before/After、複数案比較等）
- 12-20枚のスライドに十分なコンテンツ量があるか

**短いトピック入力の場合の特別処理:**

入力が短いトピック説明（1-2文、ファイルではない）の場合、コンテンツ充足度チェックはスキップし、代わりに以下を質問する:
1. プレゼンの目的（research / business / technical / educational）
2. 想定聴衆（専門家 / 一般 / 経営層 等）
3. 特に含めたいポイントや主張があれば
4. 使いたいデータや事例があれば

#### 3c. 診断結果に基づく判断

**すべて充足の場合:**
「ドキュメントの情報量は十分です。スライド生成を開始します。」と伝え、ステップ4へ進む。

**欠落項目がある場合:**
以下の手順でユーザーに質問する:

1. まず診断サマリーを簡潔に提示する（各項目の充足状況を表で表示）
2. 欠落・部分的な項目について、具体的で答えやすい質問を提示する
3. 関連する質問はグループ化してまとめて聞く（1問ずつ聞かない）
4. 1回の質問で最大5項目にする。それ以上ある場合は重要度順に5つに絞る
5. 質問の末尾に以下を必ず添える:

> 不足情報があれば教えてください。「このまま作成して」と伝えていただければ、現在の情報でスライドを生成します。

**質問の書き方ルール:**
- 日本語で自然な口調にする（質問の言語はドキュメントの言語に合わせる）
- 具体的に何が必要かを示す（例: 「この調査の対象者数と調査期間を教えてください」）
- 選択肢がある場合は提示する（例: 「プレゼンの目的は以下のどれに近いですか？ (1) 研究発表 (2) ビジネス提案 (3) 技術説明 (4) 教育・講義」）

#### 3d. ユーザー回答後の処理

- ユーザーが情報を提供した場合:
  - 提供された情報を元のドキュメント内容に統合し、残りの欠落を再評価する
  - 重要な欠落がまだ残っている場合: **1回だけ**追加質問する（最大2ラウンドで打ち切り）
  - 十分になった場合、またはユーザーの2回目の回答後: ステップ4へ進む
- ユーザーがスキップ指示をした場合:
  - 「現在の情報でスライドを生成します。不足部分は一般的な内容で補完、または該当セクションを省略します。」と伝える
  - ステップ4へ進む

**スキップと認識するフレーズ:**
「このまま作成して」「このまま進めて」「スキップ」「skip」「これで全部」「情報はこれだけ」「十分です」「大丈夫です」

### 4. コンテンツ分析

ステップ3で確定した目的と、ユーザーからの追加情報を統合した上で、コンテンツ要素を識別する:

- テキスト段落 → テキスト系パターン
- 数値データ → メトリクス/テーブル系パターン
- 手順/プロセス → ステップ/フロー系パターン
- コード → コード系パターン
- 比較/対比 → 比較系パターン
- 図表が必要 → SVG 自動生成対象

### 5. スライド構成設計

`docs/pattern-guide.md` のセクション2「プレゼン目的からスライド構成を選ぶ」に従い、スライド構成を決定する。

**スライド枚数の目安:**
- research: 12-18枚
- business: 10-16枚
- technical: 12-20枚
- educational: 10-16枚

1プレゼンテーション = 12-20枚を目安とする。

### 6. パターン選択

各スライドに最適なパターンを割り当てる。

1. `docs/pattern-guide.md` のセクション1「コンテンツの種類からパターンを選ぶ」を参照
2. 各スライドのコンテンツに最も合うパターン番号を選択
3. `slides/example.md` から該当パターンの実装を参照してコードを書く

**パターン選択の優先順位:**
- コンテンツの性質に最も合致するパターンを優先
- 同じパターンの連続使用は避け、視覚的変化をつける
- セクション区切り（Pattern 3/4）を論理的な区切りに挿入

### 7. SVG 図表の自動生成判定

`docs/pattern-guide.md` のセクション3「SVG図表の自動生成判断基準」に基づき、SVG 生成が必要なスライドを特定する。

**生成手順:**
- 技術図表（アーキテクチャ、フローチャート、シーケンス図、比較図、階層図）→ `svg-creator` スキルの仕様に従い SVG を生成
- ビジネス図表・データビジュアライゼーション・概念イラスト → `image-creator` スキルの仕様に従い SVG を生成
- 生成した SVG は `assets/svg/` に保存
- スライド内に `![説明](./assets/svg/ファイル名.svg)` で埋め込む

### 8. スライドファイル生成

以下の構造でファイルを生成する:

```
1. frontmatter（template.md からコピー、header/footer を適切に設定）
2. Tailwind CDN スクリプトブロック（template.md からコピー）
3. タイトルスライド
4. 本文スライド群（--- で区切り）
5. 締めスライド（Thank You / Q&A）
```

**遵守事項（docs/style-guide.md より）:**
- タイトルにコロン（:）を使わない
- 感嘆符（!）を使わない
- 装飾的な絵文字を使わない
- 1スライド = 1つの明確なメッセージ
- 箇条書きは1スライド最大5個
- アクセントカラーは1スライド最大2色（Navy + Teal）
- 本文テキストに純粋な黒（#000000）を使わない → Dark Gray（#334155）を使用
- `<div>` 内に Markdown を書く場合、開始タグ直後に空行を入れる
- HTMLタグ内で `$...$` 数式を使わない → Markdown 段落として記述

### 9. 出力ファイル

- ファイルパス: `slides/` ディレクトリに保存
- ファイル名: 入力内容から適切な英語スラッグを生成（例: `ml-performance-research.md`）

### 10. 完了報告

以下を報告する:
- 生成ファイルパス
- スライド構成サマリー（各スライドのタイトルとパターン番号）
- 生成した SVG ファイル一覧（あれば）
- プレビューコマンド: `npm run preview:file -- slides/ファイル名.md`
